# 技术实现说明

## 一、总体架构

菜小智采用“端侧交互 + 模型服务 + 食品规则 + 决策编排”分层架构。HarmonyOS 客户端基于 ArkTS、ArkUI 与 Stage 模型实现；网页原型用于零依赖评审演示。真实部署时，Camera Kit 负责用户主动拍摄，视觉模型识别食材类别和可见新鲜度特征，规则引擎校验食品安全与保存建议，大模型结合用户条件生成购物和菜谱方案。

## 二、数据流

1. 用户拍摄食材，客户端进行尺寸压缩、方向校正和最小化采集。
2. 视觉模型输出食材类别、置信度与可解释观察点。
3. 食品规则层给出参考价格区间、推荐购买量、保存期限和风险提示。
4. 决策层融合人数、预算、口味、技能、健康目标和家庭库存。
5. 输出一餐方案、定量购物清单与分步菜谱。
6. 完成烹饪后更新库存和饮食记录，形成下一轮推荐依据。

## 三、创新点

- **从识别工具升级为决策闭环**：结果直接进入搭配、采购、烹饪和库存反馈，不停留在“这是什么”。
- **多约束一餐生成**：同时平衡营养、预算、库存、偏好、人数与烹饪难度。
- **可解释的新鲜度辅助**：展示色泽、表皮、霉斑等依据，并明确不确定性和安全边界。
- **线下采购友好交互**：核心操作压缩为“拍一下、看重点、补齐单、照着做”。
- **以减少浪费为目标**：优先消耗临期库存，提供价格过高时的等价替代。

## 五、隐私与安全

默认以最小必要原则处理图像；没有用户主动操作不启动相机。演示服务不上传真实图片。真实版本需采用传输加密、访问鉴权、日志脱敏和可撤销授权。新鲜度与价格均为辅助信息；对于异味、渗液、霉变和包装异常等情况，系统优先提示停止食用。
